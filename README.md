# 사양서 검색 — 부품 Spec. Sheet

> 🌐 **데모: [https://aebonlee.github.io/hd-project17/](https://aebonlee.github.io/hd-project17/)** · 저장소: https://github.com/aebonlee/hd-project17

생성형 AI 업무자동화 전문가과정 [1차수] 프로젝트 — 기획: **류제찬** (HD건설기계)

메인 서버 폴더에 쌓인 **사양서 엑셀을 색인해 두고**, 검색창에 품번이나
“호스 검색해줘” 같은 말을 넣으면 **사양서를 화면에 그대로 펴 주고**,
없으면 **등록을 요청하라고 안내**하는 사내 검색 사이트입니다.

---

## 무엇이 문제였나

품번을 알면 폴더에서 파일을 찾을 수 있습니다. 파일 이름이
`420108-02540 HOSE,GAS;OXYGEN TWIN _FM USE.xlsx` 이니까요.

**품번을 모르면 못 찾습니다.** "산소호스가 필요한데 품번이 뭐지"에서 막힙니다.
그래서 검색은 품번뿐 아니라 **품명·모델·용도**로도 걸려야 합니다.

## 세 가지 길

| 이용자가 하는 것 | 시스템이 하는 것 |
|---|---|
| `420108-02540` | 그 사양서를 편다 |
| `호스 검색해줘` | **“산소호스와 실리콘 고열호스가 조회 되었습니다. 어떤 걸 찾으시나요?”** → `산소호스 알려줘` → 편다 |
| `건조기 필터` | “저장 되어있는 파일이 없습니다. 내용을 재확인 하거나 생산기술팀에 사양서 등록을 요청 하세요” |

되물을 때 **하나를 골라 주지 않습니다.** 고르는 것은 사람입니다.

말끝을 알아듣는 데 **LLM 을 쓰지 않았습니다.** API 키가 있어야 도는 시스템은
사내 승인이 날 때까지 아무도 못 씁니다. `검색해줘`·`알려줘`·`좀`·`를` 같은
꼬리말을 떼는 것으로 기획서의 대화가 그대로 재현됩니다.

## 오늘 검색 기록

오른쪽 아래 작은 창에 오늘 무엇을 검색했는지 남습니다.
그중 **못 찾은 검색어가 이 시스템에서 가장 값진 자료입니다** — 등록해야 할
사양서 목록이기 때문입니다. 많이 찾은 것이 위로 오고, 「등록 요청 목록 복사」로
생산기술팀에 바로 붙여 넣을 수 있습니다.

기록에 **연락처는 남기지 않습니다.** 검색어에 전화번호나 메일 주소가 섞여
들어오면 가운데 자리를 지웁니다. 화면에서 한 번, 서버 트리거에서 또 한 번
지웁니다 — 둘 중 하나만 있으면 REST 를 직접 부르거나 데모 모드일 때 새어 나갑니다.

## 진짜 어려웠던 것 — 양식이 일정하지 않다

기획자가 보낸 실제 사양서 10건을 파싱해 보고 안 것입니다.

| 무엇이 | 얼마나 |
|---|---|
| 시트 이름 | **7종** (`부품사양서` / `(양식) 부품사양서` / `부품사양서 (양식)` / `부품사양` / `구매목록` / `에어 호스` …) |
| 품번 위치 | 제목 줄이 밀려 **B3 인 파일과 B4 인 파일**이 섞임. 값이 `C` 를 건너뛰고 `D` 에 있는 파일도 있음 |
| 같은 항목의 다른 이름 | `제조 Maker` = `메 이 커`, `모델 및 규격` = `규 격 및 모 델`(어순이 뒤집힘) |
| 사양서가 아닌 문서 | 10건 중 1건은 **구매 목록**이었다 |
| 파일명 ↔ 내용 | 10건 중 2건이 어긋났다 |
| 파일 형식 | 구형 `.xls` 3건 + `.xlsx` 7건 |

**10건 중 공통으로 채워져 있는 항목은 품번과 품명 둘뿐입니다.**

그래서 `scripts/build_index.py` 는 **위치를 믿지 않습니다.** 라벨을 찾고 그
오른쪽 칸을 읽습니다. `C4` 를 읽는 파서는 10건 중 2건을 **조용히** 틀리게
읽습니다 — 틀렸다는 사실조차 남지 않는 것이 가장 나쁩니다.

### 못 읽은 칸을 지어내지 않습니다

항목마다 세 가지 상태를 구분합니다.

| 상태 | 뜻 | 화면 |
|---|---|---|
| `filled` | 값이 있다 | 값을 보여 준다 |
| `blank` | 라벨은 있는데 칸이 비어 있다 | **(비어 있음)** 이라고 적는다 |
| `missing` | 이 양식에 그 항목이 아예 없다 | 줄을 그리지 않는다 |

둘을 뭉뚱그리면 화면에서 똑같이 `-` 로 보입니다. 사양서에 원래 없는 항목인지
담당자가 안 적은 것인지 알 수 없으면, 무엇을 보완해 달라고 요청할 수가 없습니다.

## 기획서의 물음표에 답합니다 — “특정 폴더(D/B?)”

기획서에 물음표가 붙어 있었습니다. DB 로 옮겨야 하는지 자체가 질문이었습니다.

**폴더를 그대로 둡니다. DB 로 옮기지 않습니다.**

- 사양서를 만드는 사람은 앞으로도 엑셀로 만듭니다. DB 입력 화면을 만들면
  **일이 하나 늘 뿐** 아무도 쓰지 않습니다.
- `scripts/build_index.py` 가 폴더를 훑어 **색인(JSON)** 을 만듭니다.
  폴더가 원본이고 색인은 언제든 다시 만들 수 있는 파생물입니다.
  둘이 어긋나면 폴더가 옳습니다.
- 사이트는 색인만 읽습니다. **엑셀 원본도 사진도 저장소에 넣지 않습니다.**
  기획자가 보낸 10건이 이미 4MB 입니다. 수천 건이면 GB 가 됩니다.
  색인에는 어느 파일의 몇 번째 시트인지만 남기고 실물은 있던 자리에 둡니다.

```bash
# 사내에서 (openpyxl, xlrd 필요)
python3 scripts/build_index.py "//서버/공유/사양서 모음" -o js/index-data.js
```

돌리면 이렇게 알려 줍니다.

```
10 건 → js/index-data.js
  종류: desc 3, purchase 1, spec 6
  ⚠ 사양서가 아닌 파일 1 건 (검색 결과로 내주지 않습니다):
     300644-00023 REMOCON,TRANSMITTER.xlsx [purchase]
```

## 규칙으로 막은 것

| # | 규칙 | 어디서 |
|---|---|---|
| 1 | 칸을 위치가 아니라 **라벨로** 찾는다 | `build_index.find_field` |
| 2 | 같은 항목의 다른 이름을 하나로 본다 | 같음 |
| 3 | 파일명과 내용의 품번이 다르면 **조용히 고르지 않고** 표시한다 | `build_index.resolve_part_no` |
| 4 | 사양서가 아닌 문서를 사양서로 내주지 않는다 | `build_index.classify` + `Logic.isSearchable` |
| 5 | 못 읽은 칸을 지어내지 않는다 (`blank` ≠ `missing`) | `Logic.fieldState` + `check` 제약 |
| 6 | 후보가 둘 이상이면 하나를 고르지 않고 되묻는다 | `Logic.respond` |
| 7 | 없을 때 문구는 기획자가 준 그대로 | `Logic.NOT_FOUND` |
| 8 | 품번은 **6자리-5자리** | `Logic.isPartNo` + `check` 제약 |
| 9 | 검색 기록에 연락처를 남기지 않는다 | `Logic.maskContact` + `search_log_mask` 트리거 |
| 10 | 오늘 기록은 오늘 것만 | `Logic.todayLog` |

규칙을 두 곳에 적은 이유가 있습니다. anon 키는 브라우저에 그대로 실리는
공개 값이라, **REST 를 직접 부르면 화면 규칙은 전부 통과합니다.**
`supabase/schema.sql` 의 제약·트리거·RLS 가 진짜 방어선입니다.

## 개발 / 테스트

```bash
node test/logic.test.js          # 검색 규칙          75
node test/store.test.js          # 데모 저장소 한 바퀴 37
node test/server.test.js         # 서버 어댑터        31
python3 test/test_build_index.py # 엑셀 파싱 규칙     42
node test/smoke.browser.js       # 브라우저에 실제로 띄워  28
./scripts/sqltest/run.sh         # 진짜 PostgreSQL 에 schema.sql 적용  31
```

`scripts/sqltest/run.sh` 는 임시 클러스터를 만들어 쓰고 지웁니다. 기존
PostgreSQL 설치에 영향이 없고, 운영 데이터베이스에서는 실행되지 않도록 가드가
들어 있습니다. PostgreSQL 이 없으면 `apt-get install postgresql` 또는
`brew install postgresql@17` 후 다시 실행하세요.
(`initdb` 는 root 로 돌지 않습니다. root 라면 일반 사용자로 실행하세요.)

### 파일 구성

| 파일 | 하는 일 |
|---|---|
| `js/logic.js` | **검색 규칙 전부.** 화면도 저장소도 모릅니다 |
| `scripts/build_index.py` | **엑셀을 읽는 규칙 전부.** 사내에서 돌려 색인을 만듭니다 |
| `js/store.js` | 데모 저장소 (localStorage). 색인과 검색 기록만 담습니다 |
| `js/supabase-store.js` | 서버 어댑터. `store.js` 와 **같은 모양**이라 갈아 끼울 수 있습니다 |
| `js/app.js` | 화면. 판정은 하지 않고 `logic.js` 의 결과를 그리기만 합니다 |
| `js/seed-data.js` | 샘플 색인 — `scripts/gen-seed.py` 가 만듭니다. 손으로 고치지 마세요 |
| `supabase/schema.sql` | 테이블 · 제약 · 트리거 · RLS. 화면과 **같은 규칙**을 서버에서 다시 막습니다 |
| `test/smoke.browser.js` | 브라우저에 실제로 띄워 — 규칙 테스트가 못 잡는 자리 |

샘플에는 **기벽까지 넣었습니다** — 구형 양식, 구매목록, 품번이 어긋난 건,
비어 있는 칸. 매끈한 샘플만 넣으면 화면이 매끈해 보이고, 정작 실물을 넣는 날
무너집니다.
